## 2. Что уже написано

### Приватность: первый неполный этап режима призрака

`AyuPrivacySettings` хранится отдельно в Postbox каждого аккаунта. Все переключатели по умолчанию выключены. При добавлении новых полей сохраняй обратную совместимость Codable через `decodeIfPresent`.

- `hideOnline`: фильтрует сигнал, поступающий в `AccountPresenceManager`. Переключение при активной онлайн-сессии приводит к отправке offline. Сетевой keepalive специально не меняется.
- `hideTyping`: проверяется перед `setTyping` и `setEncryptedTyping`. Отмена ранее опубликованной активности и сигнал speaking в групповом звонке разрешены.
- `keepChatsUnread`: блокирует автоматическое применение max-read-index, прочтение из notification/id-пути и автоматические действия чтения при показе сообщений/реакций.
- UI: «Настройки → Конфиденциальность → Ayu» — кнопка справа в навигации; четыре переключателя и переход в журнал.

**Это не полный ghost mode.** Ручное «прочитать всё», просмотры историй, отметки прослушивания/просмотра медиа и другие API-пути ещё нужно разобрать. Уже отправленный запрос не отозвать. На реальные аккаунты поведение пока не проверялось.

### Локальная текстовая история

- `saveMessageHistory`: отдельный выключенный по умолчанию переключатель.
- Перед применением `.EditMessage`, `.DeleteMessages`, `.DeleteMessagesWithGlobalIds` в `replayFinalState` сохраняется предыдущий доступный текст; для правки сохраняется также новый текст.
- Отдельный ключ Postbox, разделение по аккаунтам; последние **500** событий, до **4096 символов** на текст. Последовательные одинаковые события не дублируются.
- UI журнала: новые события сверху, дата, ID чата/сообщения, старый/новый текст; кнопка очистки.
- Медиа не сохраняются; секретные чаты и `containsSecretMedia` пропускаются. Медиа с подписью могут дать снимок подписи, но не сам файл.
- Удаление продолжает нормально применяться к основной базе Telegram. Это **отдельный журнал**, а не полноценный anti-recall с оставлением удалённой «пузырьковой» записи в чате.
- Если сообщение не было в локальной базе до правки/удаления, старого текста нет. Историю нельзя восстановить задним числом с сервера.

## 6. Как быстро продолжать изменения

1. Текущая рабочая папка уже содержит раскрытые патчи. Меняй Swift-файлы, не пытайся накатывать эти патчи поверх них повторно.
2. Проверь модели, затем полный iOS target. Новые изменения должны попасть в воспроизводимую серию патчей в правильном порядке либо быть перенесены непосредственно в исходники репозитория.
3. Если меняешь патч, обнови его зависимые патчи, YAML и SHA-256 в `ayu_prepare.py`. Не обновляй хеши только ради скрытия несовпадений: сначала проверь diff и результат свежего применения.
4. Когда появится нормальная Git-аутентификация, можно перейти от патчей к обычным исходным коммитам. В одном переходе убери применение патчей из CI и обнови helper; нельзя одновременно закоммитить раскрытые файлы и повторно применять к ним патч.
5. Git remotes: `origin` — пользовательский Ayu-iOS, `upstream` — TelegramMessenger/Telegram-iOS. В момент передачи Git Credential Manager настроен, но сохранённой GitHub Git-авторизации не обнаружено. Не ожидай, что `git push` уже работает.
6. Пока публикация делалась через вошедший GitHub в Brave. Загрузка через file chooser заблокирована настройкой расширения `Allow access to file URLs`; рабочий обход — веб-редактор и ввод текста подготовленного файла. Не включай расширению новые права без необходимости.
7. Browser automation: использовался browser id `3` (Brave), но в новой сессии обязательно проверь доступные вкладки. Не полагайся на старые element indexes. Для auth/OTP пользователь входит сам; не собирай его коды в чат.

- Отдельные настройки/политики для прочтения, прослушивания голосовых, просмотра видеосообщений, stories и реакций; охватить все API-пути, темы/форумы, mono-forum и notification extensions.

## 8. Чего не делать при продолжении

- Не говорить, что «все функции перенесены», что ghost mode полностью скрывает активность или что IPA уже готов.
- Не считать прошедшие чистые модельные тесты проверкой UI или работы MTProto.
- Не выдавать simulator IPA за файл для iPhone; не использовать тестовые API-значения для реального аккаунта.
- Не публиковать API hash, токены, provisioning credentials или generated configuration. `build-input` уже игнорируется Git.
- Не удалять локальный overlay/reset-ить папку ради чистого `git status` без сохранения изменений.
- Не переписывать весь upstream и не исправлять посторонние подсистемы. `TelegramCore` не должен импортировать UIKit/Display; наружу используй TelegramEngine, сохраняя существующие ограничения Postbox.

Пользователь отложил вход на https://my.telegram.org/apps; сказал, что войдёт позже. Это не блокирует работу над кодом и simulator compile check. Для рабочего клиента попроси сохранить собственные `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в группе `telegram_api` Codemagic, а не присылать их в чат.
