# Ayu iOS — рабочая база форка

Основа: TelegramMessenger/Telegram-iOS, commit
`279f89e4d4f63f17227bf877dc3d8990f22ecd58`.
Это не официальный AyuGram. Написаны первые настройки приватности и локальный
текстовый журнал правок/удалений. Полная сборка, UI и реальное поведение аккаунта
ещё не подтверждены; это незавершённый форк.

**Для следующей ИИ:** сначала прочитать [AI_HANDOFF.md](AI_HANDOFF.md).
Репозиторий уже создан: https://github.com/lifelovv/Ayu-iOS.
Приложение Codemagic: https://codemagic.io/app/6ae82f7e1550ea98e90785a9/settings.

В опубликованном репозитории исходные изменения хранятся в `ayu-privacy.patch`
и `ayu-history.patch`, применяемых в таком порядке. На свежем клоне запусти
`python ayu_prepare.py`; на текущей локальной папке — `python ayu_prepare.py --verify`.
Скрипт проверяет итоговые хеши и не перезаписывает конфликтующие изменения.

## Сборка без своего Mac

1. Создай свой fork https://github.com/TelegramMessenger/Telegram-iOS на GitHub.
   Загрузи изменения из этой папки в свой fork через Git. Не загружай исходники
   отдельным ZIP: Git сохраняет ссылки на нужные версии submodules.
2. В Codemagic добавь этот репозиторий как приложение с конфигурацией
   `codemagic.yaml`. Сам YAML не запускает сборку и не публикует приложение.
3. Получи собственные `api_id` и `api_hash` на https://my.telegram.org/apps.
   В Codemagic создай группу переменных `telegram_api` и добавь секретные
   `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. В Git и чат их отправлять не нужно.
4. Выбери workflow `ayu-ios-ipa` и запусти вручную.
   Требуется образ Apple silicon с Xcode из `versions.json` (сейчас 27.1).
   Если Codemagic не предлагает эту версию, этот checkout пока нельзя собирать
   на доступном образе: потребуется согласованный переход на поддерживаемый тег
   Telegram или ожидание образа. Подмена версии проверкой `override` не решает
   несовместимость SDK/Swift.
5. При успешной сборке скачай `Ayu-iOS-resign-required.ipa` из Artifacts.
   Тестовая подпись взята из upstream; она не даёт права установки на iPhone.
   IPA нужно переподписать своим средством установки на Windows. Совместимость
   выбранного средства с расширениями, app groups и push нужно проверять на устройстве.

Workflow `ayu-ios-simulator` проверяет компиляцию для ARM64-симулятора;
собственные API-данные для него не нужны. Он использует значения только для
компиляции, с которыми нельзя войти в Telegram. Его результат не устанавливается
на iPhone. Ни один workflow не публикует
релизы и не отправляет сборку в TestFlight. Первая полная сборка может не
уложиться в лимит времени/ресурсов аккаунта; кэш Bazel включён для следующих запусков.

## Что важно для подписи

Промежуточная сборка сохраняет bundle/team IDs Telegram, чтобы соответствовать
тестовым профилям upstream. Это технические идентификаторы для сборки, а не
готовая идентичность собственного приложения. При реальной подписи нужны свои
идентификаторы, entitlements и профили. Для TestFlight потребуется отдельная
настройка подписи с Apple Developer, включая профили расширений.

Перед распространением нужно заменить название/иконки и соблюдать лицензии
исходников. Оригинальный README и лицензии сохранены.

Тестовые provisioning profiles upstream истекли 30 октября 2026. Для симулятора
профили отключены в YAML; путь выпуска IPA для устройства ещё нужно довести.
Пока нельзя считать workflow устройства рабочим установочным решением.

## Целевые функции

Запрос: все функции AyuGram. Их точный перечень нужно закрепить по версии
AyuGram Android/Desktop; у этих клиентов различаются возможности.

Следующие этапы реализации:

- настройки форка с раздельными переключателями;
- режим призрака: контроль отправки статуса, прочтения и набора текста;
- локальный журнал правок и удалений с очисткой и изоляцией аккаунтов;
- интерфейс просмотра истории и восстановление локально сохранённых данных;
- оформление, фильтры и остальные функции выбранной версии AyuGram;
- сборка в CI и проверка входа, синхронизации, уведомлений на iPhone.

История может содержать только данные, которые клиент успел получить и сохранить.
Сообщения, удалённые до их получения клиентом, восстановить с серверов нельзя.
